# Feature Specification: 定时分析与复盘分析

**Feature Branch**: 当前工作分支（不自动提交）
**Created**: 2026-11-04
**Status**: Ready
**Input**: 用户要求“请增加定时分析和复盘分析两个功能”。

## User Scenarios & Testing

### User Story 1 - 配置每日定时任务 (Priority: P1)
管理员在UI设置每日北京时间、任务类型（赛前分析或赛后复盘）、业务日偏移和启停。用户可看到下次执行时间、最近执行状态及结果入口。

**Why this priority**: 无需守在页面手动启动任务。
**Independent Test**: 保存停用任务、启用并推进模拟时钟，确认仅执行一次并保留记录。
**Acceptance Scenarios**:
1. Given 未配置任务，When 打开定时分析，Then 默认不启动任何模型调用。
2. Given 已启用计划，When 到达执行时间且服务运行，Then 60秒内提交一次任务，重复检查不重复提交。
3. Given 服务重启或离线错过时刻，When 恢复，Then 保留记录；仅补最近15分钟内一次，过期记录跳过，不集中补跑历史任务。
4. Given 同时有分析运行，When 计划到期，Then 明确记录繁忙跳过，不把其他日期的任务当作本次成功。

### User Story 2 - 按日期复盘与查阅 (Priority: P1)
管理员选择业务日并发起复盘；页面查看逐场原选项、比分、半场、命中状态、分支与模拟返还、分栏命中统计和资料缺口。

**Why this priority**: 复盘必须能追溯原票，不凭赛后印象改票。
**Independent Test**: 固定官方赛果和原票，验证足球/篮球不同玩法结算，再次运行不会重复计数。
**Acceptance Scenarios**:
1. Given 存在冻结原票，When 获取官方终场赛果，Then 使用原盘口和原赔率逐项、逐腿、逐分支结算，并更新可查询台账。
2. Given 缺赛果、取消、球队身份冲突、未知玩法或走盘，When 复盘，Then 明确待核，不自动计输、不推测退款。
3. Given 缺半场比分，When 复盘半全场，Then 该项待定，其他可结算玩法正常处理。
4. Given 同日重复复盘或赛果更正，When 完成，Then 保存新复盘版本、台账采用最新有效版本而非累计重复；原票与旧复盘不变。
5. Given 尚未发布草稿或没有标准化原票，When 复盘，Then 不将其当作最终推荐，不猜测异构历史原票结构。

### User Story 3 - 权限与边界 (Priority: P2)
查看者可阅读复盘，不可触发或修改计划；管理员操作需防伪令牌，操作留痕。
**Independent Test**: 未登录、viewer、admin分别访问及提交表单。
**Acceptance Scenarios**:
1. Given viewer，When 提交任务或计划变更，Then 拒绝。
2. Given 任意任务成功，When 查看产物，Then 不自动标记推荐已发布，不推送、不下单，不编造概率、归因或真实金额。

### Edge Cases
- 午夜跨日与足球跨夜业务日；篮球客:主队序。
- 网络超时、分页异常、重复/歧义赛果、无原票。
- 多Web进程竞争、任务启动失败、进程中断、计划重复编辑和停用。
- 盘口/赔率/半场缺失；比分7+及其他；双平多分支。

## Requirements

### Functional Requirements
- **FR-001**: 提供定时计划列表、添加/编辑和停用，时间采用Asia/Shanghai；支持当日或前1/2日偏移，每日最多12个计划。
- **FR-002**: 保存计划、下次执行与最近执行记录；重启不丢失，单次到期最多提交一次，失败/跳过如实展示。
- **FR-003**: 赛前计划复用现有分析任务与草稿隔离；复盘计划使用独立后台任务。
- **FR-004**: 复盘冻结所用标准化原票、官方响应和哈希，按匹配身份校验的赛果确定性结算；保留所有原始版本。
- **FR-005**: 台账最终推荐、单场、六类、结构研究、梦想分栏；待定不计命中率分母；实际金额/返还恒null。缺事前p_mkt不补写；未知错误归因明确未评估。
- **FR-006**: 新复盘不覆盖正式报告，不更改发布状态，不编辑history；可重复刷新，不重复累加。
- **FR-007**: 管理员变更/触发需认证与防伪令牌，并记录操作日志；界面在375px可用。

### Key Entities
- 计划：类型、每日时刻、偏移、启停、下次执行、创建人。
- 执行记录：应执行时刻、业务日、任务引用、状态、失败或跳过原因。
- 复盘版本：业务日、原票/赛果快照及哈希、逐项结算、分栏统计、替代关系。

## Success Criteria

### Measurable Outcomes
- **SC-001**: 用户可在2分钟内配置一个停用或启用的每日计划。
- **SC-002**: 正常在线到期计划在60秒内提交，重复检查或两个服务进程不产生重复任务。
- **SC-003**: 固定赛果用例中队序、盘口、半全场及复式分支计算全部符合预期，未知数据不被记为输。
- **SC-004**: 重复复盘后各分栏推荐数量不增加，原票/历史报告字节保持不变。
- **SC-005**: 权限、防伪、断网与启动异常验证通过；桌面/375px完成保存和查看流程。

## Assumptions
- 默认所有计划停用，管理员明确启用后才可自动消耗本机CLI额度；不自动新增生产计划。
- 每日计划而非任意cron；晚场等名称由计划名称表达，不改变业务推荐分段规则。
- 初版复盘仅确定性结算；2026-11-05用户修订由`specs/009-ai-decisions/`覆盖：新正式复盘必须在结算后取得Claude/Codex实际AI分析返回，失败不提升本次台账。归因无非赔率证据仍须明确未知，不允许编故事。
- 旧数据采用已知标准化台账原票，不以mtime推断异构recommendations.json最终版本；未来发布接入需单独适配。
- 官方取消/走盘的退款规则尚未实现，保持待核而非声称结算。
