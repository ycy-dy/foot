# 034 全功能与核心链路逐项验收

用户2026-11-08要求所有功能/逻辑、每个页面与按钮逐一验证，问题实施修复。关联Issue #14（核心）/#8（UI），不重复建立总审计Issue。

## 验收

1. 注册路由、页面、控制件与角色/状态完整清单，可追溯到测试或浏览器证据；无证据不得标完成。
2. 核心输入/时点/销售、研究真实AI身份、证据来源/70门禁、候选与实际分支、人工审核发布、冻结复盘/幂等都有正反测试。
3. 新推荐的引用/人工复核凭据须实际消费磁盘工件，并核task/match/option/dimension/as_of绑定；AI字段不能代替复核。原任务/原票不改，人工复核以独立覆盖层回流。
4. UI覆盖admin/viewer/匿名、桌面/手机、输入/禁用/异常/加载/终态；有副作用隔离fixture验证，不执行生产发布/消息/投注。
5. 发现缺陷先可复现红灯再实现修复；完整测试/浏览器/部署健康与限制如实记录。

## 人工复核后的新决策

管理员可显式从已复核任务发起同业务日新任务，沿用既有受限资料复用：当前规则/提供方一致、原检查点哈希和身份一致、资料在复用时限内且未开赛。原AI输出保持不变；新检查点只追加有真实凭据的claim覆盖层并保留原task/actor/time。新任务刷新官方价格且必须重新调用当前Codex做最终取舍，不复用旧决策，不自动发布。复核不是将未知维度改成已核实，也不能消除冲突或补造证据。

## 非目标

不训练独立概率模型、不保证预测/收益、不启用自动计划/通知/监听；不绕过生产OAuth、人工发布或用户输入。生产认证未完成可由隔离UI和服务集成继续验证，但必须标注范围。
