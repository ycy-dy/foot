# Feature Specification: 现有功能完整性与分析推荐可用性

**Feature Branch**: 现有工作区（不提交或重置既有修改）
**Created**: 2026-11-05
**Status**: In progress
**Input**: 用户要求“请你全部实现和优化现有功能 确保每个功能都能正常 特别是分析并推荐”。

## User Scenarios & Testing

### User Story 1 - 完成真实分析与推荐 (Priority: P1)

管理员从已有入口刷新官方资料，完成AI研究、推荐取舍并看到可理解、可核查的草稿；失败则知道失败阶段和恢复方式。

**Why this priority**: 分析并推荐是用户明确强调的核心。
**Independent Test**: 一轮受控小规模真实提供方验证与完整离线端到端验证分开记录，不用模拟结果声称模型可用。

**Acceptance Scenarios**:
1. **Given** 有效未开赛比赛和官方报价，**When** 发起分析，**Then** 冻结资料、完成价格盲研究和真实AI取舍，展示每腿理由、来源/缺口、市场基准、失败路径和撤销条件。
2. **Given** 提供方超时、限额、无效返回或上下文过大，**When** 分析失败，**Then** 有界停止/回退，保留已完成工作，明确失败阶段并支持合理续跑，不机械选腿冒充成功。
3. **Given** 原AI决策后的价格或资格变化，**When** 审核，**Then** 不静默换腿、不过期发布，保留新分析路径。

### User Story 2 - 每个现有入口有清楚的可用状态 (Priority: P2)

用户能正常浏览赛程、证据、历史、台账、统计、效果、体系版本；管理员能使用体系编辑、任务控制、调度、复盘和临场复核。

**Why this priority**: 避免孤立入口、空按钮、过时任务状态造成误导。
**Independent Test**: 按001–009规格建立现有功能验收矩阵，验证权限、空数据、错误与成功路径。

**Acceptance Scenarios**:
1. **Given** 管理员/查看者/未登录三种身份，**When** 访问现有页面和操作，**Then** 各自权限、登录恢复和防重复提交保持正确。
2. **Given** 外部依赖不可用或未配置，**When** 使用相关功能，**Then** 如实显示未配置/失败，不以空页面或假成功替代。

### User Story 3 - 更新可靠且历史不变 (Priority: P2)

**Why this priority**: 优化不能损坏已发布记录或生产服务。
**Independent Test**: 全量回归、桌面/手机浏览器操作、重启和健康检查，冻结原票保持原样。

**Acceptance Scenarios**:
1. **Given** 已发布记录和成功复盘，**When** 新一轮失败或更新程序，**Then** 不覆盖历史、不把旧结果追溯标成AI结果。
2. **Given** 新代码已验收，**When** 部署重启，**Then** 服务健康且认证边界保持。

### Edge Cases

无比赛、停售、窗口外、过期/陈旧快照、只有一场、无合规组合、两提供方皆失败、输出过长或不完整、跨阶段取消/续跑、进程退出、跨工作进程竞争、无AI历史版本、规则变化、未知赛果、通知未配置。

## Requirements

### Functional Requirements

- **FR-001**: 核对001–009现有功能并列清已验证、修复及外部未验证项；不以过期未勾任务误认功能缺失。
- **FR-002**: 分析/推荐/复盘推理保留本机Claude优先、Codex回退；每次真实结果有输入、返回、提供方及哈希，不伪造成功。
- **FR-003**: 优化输入规模、执行预算、错误展示和检查点恢复中发现的问题，不丢失证据、候选或放宽排名/业务门槛。
- **FR-004**: 新/旧、草稿/发布、事实/AI解释、市场基准/模型概率清楚区分；不把确定性候选称为完成的AI推荐。
- **FR-005**: 现有功能保持角色、CSRF、冻结和审核边界；缺配置时明确不可用。仅修复/完成当前规格，不新增无关能力。
- **FR-006**: 对修复增加回归，完整离线端到端与真实依赖结果分开保存；最终全量验证后部署。
- **FR-007**: 不自动发布、发送通知、启用计划、修改历史或投注；不改全局账户/模型配置，不披露凭证。

### Key Entities

- **功能验收项**：所属规格、入口、前置依赖、测试证据、缺陷和验证状态。
- **分析轮次**：冻结来源、逐场证据、AI决策、阶段预算、检查点、恢复状态。
- **真实依赖验证记录**：时间、提供方、输入/返回哈希、成功或明确错误、范围限制。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 当前全部可见功能均出现在验收矩阵，不将未实际验证项写成成功。
- **SC-002**: 分析推荐的成功、提供方回退、失败续跑、取消和审核拒绝路径均有可重复验证。
- **SC-003**: 本次确证缺陷逐项修复或明确记录外部阻塞，不留静默失败或模拟成功。
- **SC-004**: 全量回归零失败，桌面与375px手机核心操作可完成；部署健康检查成功。

## Assumptions

- “全部”限定于现有001–009规格及现有入口，不等于保证预测命中、盈利或外部服务永远可用。
- 复用项目内已授权配置与原生账户，常规开发测试部署主动执行。必要的小规模真实依赖测试有界运行，测试不发布。
- 外部网络、CLI账户、钉钉真实登录与投递仍是可独立失败的依赖；未实际测试不能宣称已认证。
