# Implementation Plan

## 现状与边界

001–009和共享工作区已有大量实现，不能通过重写/回滚或仅勾任务伪装完成。父进程负责分析引擎、真实依赖与集成验收；独立只读检查非核心功能，返回可复现缺陷后再分配修复。所有shell命令用rtk。

## 顺序

1. 建立可见功能和规格覆盖矩阵，先以现态测试和受控真实依赖探测建立基线。
2. 优先解决分析推荐中的实际阻塞：提供方命令兼容、结构契约、输入规模、预算、断点恢复、错误与状态展示。
3. 对独立核查中确证的辅助功能缺陷增补回归并修复；只补现有规格，不扩展无关能力。
4. 完整离线全链路、隔离真实Chrome、受控小规模真实CLI/官方数据验证分别记账。
5. 更新任务与验收矩阵；全量pytest通过后deploy/restart.sh并检查健康和认证。

## Complexity Tracking

复用现有模块、CLI账户、SQLite和launchd，不引入新服务或依赖。若实际上下文容量阻塞，需要缩小重复字段或按完整决策单元分阶段，保留所有候选/排序和完整输入可追溯，不设置机械回退。未经确认的新业务策略不实现。
