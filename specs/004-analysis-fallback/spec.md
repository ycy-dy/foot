# Feature Specification: 重新分析优先 Claude，失败回退 Codex

**Created**: 2026-11-04 | **Status**: Implemented（草稿执行已上线；自动审核发布不在本次范围）
**Input**: “重新分析按钮 使用claude，如果claude [异常] 或者无法使用，则使用codex”。

## 范围

将现有仅刷新赔率的管理员按钮接入真正的后台 CLI 分析。优先 Claude；缺失、认证/限额错误、非零退出、超时或无效结果时，同一任务只回退 Codex 一次。沿用现有账户和默认模型，不复制密钥，不绕过权限。

本次交付是后台执行和可查看的完整分析草稿，不等同于原规格 T016 自动审核发布。生成文件命名为 `report.draft.md`，不得进入 `latest_report` 的已发布报告选择，也不改写历史、台账或真实投注记录。

## 验收

- admin + 有效 CSRF 才能 POST `/api/recompute`，快速返回 202 和持久化任务；官方抓取与模型调用均不占用请求线程。
- 刷新官方快照后，将所选业务日、快照时间、全部逐场数据和 V6 完整规则交给 Agent。排除已开赛赛事的新推荐，窗口外仍显示。
- Claude 成功不调用 Codex；Claude 调用失败或结果无效时只调用一次 Codex；两者失败时明确失败，不提示“分析成功”。
- 每个提供方有超时，超时清理整个子进程组。CLI 只具备研究所需工具，不启用权限绕过或写代码能力。
- 两个 gunicorn worker、多次点击和刷新不会重复启动全日任务；状态可跨进程查询，孤立任务能报告中断。
- 页面展示运行中、当前提供方、回退原因、完成/失败及结果入口；刷新后能恢复状态。
- 分析稿明确“未审核、未发布”；Markdown 渲染须防止脚本和危险链接执行，不能把模型声称通过审核当成真实审核。
- 参数、进度和错误日志不包含 token、密钥或原始敏感 CLI 输出。
- 全量测试通过后重启服务并验证健康检查。

## 测试边界

沿用 001 规格约定的公开 API 与外部 CLI 边界：真实测试数据库、固定官方快照、模拟进程启动/CLI 响应；覆盖成功、回退、双失败、超时、重复请求、权限、恢复和草稿隔离。验证本机 CLI 连通性时只用无赛事、无推荐的最小测试，不自动发布。
