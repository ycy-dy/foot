# Implementation Plan: 统一驱动规范与 Agent 路线

## Constitution Check

遵守[宪法](../../.specify/memory/constitution.md)：业务来自现行V6，真实AI不可省略，审核及人工发布不绕过，历史冻结，无投注，尊重沙箱与最小权限。保留工作区已有修改，只增量整理文档。

## 本轮设计

1. 不迁移根目录V6与历史，避免破坏体系编辑器、CLI提示词和已有引用。
2. [治理地图](../../docs/project-governance.md)承载阅读顺序、修订覆盖和规格索引；[蓝图](../../docs/sports-agent-system.md)承载产品闭环、逻辑角色、目标契约与验收路线。
3. AGENTS追加统一导航和冲突处理；保留既有业务条款，避免一次性删除摘要造成门槛遗漏。README增加入口，宪法同步真实AI原则及治理边界，目录约定登记新文档。
4. 对新增链接做本地存在性校验、审阅本轮diff、记录验证；不触碰运行时代码和配置，不执行真实模型或生产发布。

## 后续实现计划（尚未执行）

- 先审010真实验收遗留，映射现有 worker／研究／决策／发布／复盘状态和工件，形成差异表。
- 用模拟来源与CLI固定工件覆盖双运动正反路径；真实来源／提供方验收单独记账，记录预算、超时与截止，不允许用过期赛事补做赛前推荐。
- 优先复用已有Flask／SQLite／本机CLI，按最小差异补契约、幂等与日志；每个运行时变更先补规格任务和测试。
- 人工发布在隔离环境验收，真实发布需当次管理员确认；测试后使用既有部署脚本并确认健康，不启用额外服务器或默认计划。

## Complexity Tracking

不引入新Agent框架、数据库或消息队列；“研究／反方／决策”是职责隔离，可共用既有调用链。只有现有实现无法满足验收且有独立规格时，才增加运行复杂度。
