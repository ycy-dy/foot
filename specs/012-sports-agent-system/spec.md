# Feature Specification: 足球篮球 AI Agent 系统规范收口

**Created**: 2026-11-06  
**Status**: 规范整理；运行时实现与真实验收待后续执行  
**Input**: 用户要求重新整理项目驱动规范，并实现足球、篮球彩票 AI Agent 系统。

## User Scenarios & Testing

1. 新接手的 Agent 从统一入口找到业务规则、工程宪法、功能规格及验证证据，不误用旧规则或重新创建一套推荐政策。
2. 用户能分清足球与篮球的独立政策、AI与确定性程序各自职责、哪些是现有基础、哪些仍需真实验收。
3. 开发者按已有001–011规格增量交付，优先补真实研究→推荐闭环；没有AI返回、审核失败、截止或来源冲突不能标为可发布。
4. 审阅者可追踪文档整理的改动范围、链接校验及未完成项；历史和原票保持不变。

## Requirements

- **FR-001**: AGENTS为执行入口，CLAUDE只引用它；README提供人类导航，docs提供治理地图与架构，现行V6正文／YAML留在原路径。
- **FR-002**: 保留所有既有用户业务修订与执行授权；文档摘要不替代原规则，不因重组生成新业务修订或放宽门槛。
- **FR-003**: 记录V6后续覆盖条款、009真实AI决策要求以及010未完成验收；不将旧任务全部勾成完成。
- **FR-004**: 明确Claude优先、Codex回退；研究、取舍和复盘须真实返回；工具负责事实、计算、枚举和硬否决，不能伪装AI。
- **FR-005**: 蓝图覆盖采集→研究→决策→审核→人工发布→临场→结算→AI复盘→评估；足球、篮球独立政策，不自动投注／支付／发布。
- **FR-006**: 分开执行状态、推理状态、审核状态、发布状态与台账状态；目标契约不得被描述为已迁移或已部署。
- **FR-007**: 保留已有未提交变更；不移动历史、不改原票、不写凭证、不修改业务运行产物。
- **FR-008**: 本轮验证新增文档及入口链接与git差异；本轮不改代码／.env，因此不触发服务重启，不声称生产验收完成。后续运行时改动须自动化测试及现有服务重启健康检查。

## Success Criteria

- README、AGENTS、宪法、目录约定可定位统一规范与目标蓝图，无新增业务规则副本。
- 规格012具有spec／plan／tasks，规范任务与运行时待办明确分开。
- 本轮变更内新增本地Markdown链接可解析；差异无意外历史、台账或代码修改。
- 足球与篮球分别有待执行的真实验收用例，失败边界、人工发布、冻结与台账提升可检查。

## Boundaries

本轮是规范重整与系统实施路线，不承诺一轮完成所有生产能力。已有应用不重建为新技术栈，不强制多Agent并发，不新增API账号或启用付费任务。真实模型验证、影子运行与晋升单独验收，不以AI调用成功证明预测有效。
