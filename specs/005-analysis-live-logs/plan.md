# Implementation Plan: 实时执行日志与分析交互

1. SQLite 新增独立任务日志表与任务/序号索引，提供有界保存、增量读取与导出，不改写历史任务结果。
2. CLI 启用 Claude stream-json 与 Codex JSONL；在原有超时等待期间增量读取临时输出，保留进程组清理。按事件白名单提取公开活动，过滤思考、提示和敏感字段。
3. 任务编排写入阶段、回退、成功、错误事件；提供管理员增量日志接口和文本导出接口。
4. 在共享任务区域加入状态时间、阶段轨迹和日志工作区，使用现有设计变量、图标、原生筛选和跟随开关；前端纯文本渲染、游标恢复、断线重连与末批日志排空。
5. 先以真实模拟 CLI 建立回归，再测试 API、任务持久化与响应式交互。完成后更新文档，运行全量 pytest，重启 launchd 并检查 healthz。

## 设计

- 视觉：延续现有浅色/深色操作工作台，以绿色标识运行，橙色表示等待或回退，红色表示失败。
- 内容：任务状态与时间、阶段轨迹、实时日志、执行记录、未发布草稿；无需营销或装饰图。
- 交互：新事件轻微出现、运行图标转动、原生展开/收起；遵守减少动态效果偏好。

## Complexity Tracking

使用每秒增量轮询复用已有状态链路，避免 SSE 长连接占用有限 gunicorn 线程。进程输出使用 pread 读取，避免改变子进程共享的文件偏移。SQLite 仅存脱敏白名单事件，不持久化原始 CLI 输出。
