# Feature Specification: AI推理与决策返回值

**Created**: 2026-11-05
**Input**: 用户要求“复盘分析 分析推荐等推理决策都需要使用AI claude codex 返回的结果”。

## User Scenarios & Testing

1. 管理员发起手动或定时复盘：先冻结原票和核验赛果，随后必须获得真实AI复盘结果；展示AI总结、逐票分析、失败路径、缺口和改进建议，区分事实结算与AI解释。
2. 赛前逐场研究后，必须由AI审阅合规候选并返回推荐决策及理由；不把纯程序选腿或模板当作AI推荐。
3. Claude不可用或返回无效内容时回退Codex；两者均失败则本次推理未完成，不生成假AI成功结果，不提升复盘台账或可发布草稿。
4. 用户可查提供方、尝试记录、输入输出哈希；原票和旧版本不改写。

## Requirements

- **FR-001**: 沿用用户指定的本机Claude/Codex CLI与账户，不迁移SDK、不新增API凭证；Claude优先、Codex回退，清理失败不再启动另一进程。
- **FR-002**: AI负责研究、解释、风险与取舍。程序只负责数据准备、可核验计算、候选枚举和硬门槛否决，不替代AI输出决策。
- **FR-003**: 市场基准概率、联合排序、>2.5、可售性、风险否决等原有门槛不变；AI不能改写算术、原票、概率或金额，不能绕过审核。
- **FR-004**: AI返回结构化结果并验证身份/覆盖/候选合法性；无效返回进入回退。没有AI返回不得将任务标为推理完成或生成可发布新草稿。
- **FR-005**: 保存完整输入、原始返回、已验证结果、提供方与尝试记录；日志脱敏，Web安全渲染。仅有旧程序结算的历史复盘明确非AI，不追溯标记。
- **FR-006**: AI复盘失败不替换上一成功台账；纯结算函数保持离线可测试，不能冒充完整AI复盘。
- **FR-007**: 全量测试及隔离UI通过后重启服务并确认健康检查；不为验证擅自运行生产模型/启用计划。

## Success Criteria

- 模拟提供方验证Claude成功、Codex回退、双失败、结构无效、身份错误与清理失败。
- 正式后台复盘和分析汇总无法跳过AI成功返回；所有采纳决策可以定位AI响应与哈希。
- 已有结算、权限、CSRF、去重和历史冻结测试继续通过。

## Boundaries

不保证AI解释真实或预测命中，不展示隐藏思维链；只展示返回的决策理由与证据摘要。缺少非赔率证据明确仅按市场基准，不编造赛后归因；不自动发布、不通知、不投注。
