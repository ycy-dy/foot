# Implementation Plan

## 分层

- `storage/research.py`：工作流与逐场检查点、取消/续跑的原子状态；持久化使用现有SQLite。
- `services/research.py`：结构化证据契约、选项身份与验证；不依赖web。
- `services/recommendations.py`：V6确定性候选过滤、组合、六类/八结构/梦想及报告渲染。
- `engine/tasks.py`：复用单任务门禁、独立worker与脱敏日志；逐场调用CLI，结果落盘。
- `services/publications.py`：新鲜度复核、审核脚本、版本化发布、撤销与原票接入。
- `web/research.py`与模板：逐场进度、证据页、审核台与版本对比。
- 后续在同一规格内接入效果中心、临场/通知和007调度复盘。

## 执行顺序

A. 证据与检查点契约及回归 → B. 单场CLI、取消、续跑、汇总 → C. 证据/审核/发布UI及结算接入 → D. 复核、效果、版本/情景、调度通知 → E. 全量验收与部署。

工作区009已接入真实AI推荐/复盘决策，复用`engine.decisions`和`services.selection`。程序只准备算术、合规候选和否决，Claude/Codex实际返回选择及理由；双失败保留检查点，不用模板冒充AI。发布复核保留原AI决策，候选价格、排名或资格变化后要求重获AI结果。

## 设计

沿用绿色工作台、紧凑分栏表和现有导航。分析页承担任务控制与逐场状态，比赛证据页承担两队对比，审核页承担逐项问题和发布。更新局部进度与事件，阅读详情不跳动；移动端使用纵向对比，尊重减少动态效果偏好。

## 2026-11-05用户修订（规格009）

推荐汇总不再由纯程序选腿：先枚举并计算合规候选，再取得实际Claude/Codex结构化决策并验证/物化所选ID；发布只能复核冻结决策，不能静默重新选择。复盘也必须取得AI实际分析返回，确定性结算只承担核算，不冒充推理。业务门槛、草稿审核和历史冻结不变。

## 边界

复用007已存在的定时/复盘实现并验证，不覆盖其他未提交修改。沿用默认CLI账户、模型与最小研究权限。规则变化只检测与阻断，不擅自改用户策略。新增逐场/整轮执行预算属于运行配置，不代表预测能力。真实外部通知保持显式配置和启用，不开发下注接口。
