# 后台分析、证据与发布

## 检查点与运行预算（规格008）

分析按钮总任务为“请根据最新分析和推荐体系 分析和推荐今天的比赛”。当前policy指定的AI提供方在独立受限任务中运行（当前Codex CLI；不静默混合回退），沿用既有账户和默认模型。每轮将总请求、明确业务日及现行AGENTS/体系MD/YAML冻结到输入；逐场证据和最终AI取舍是该总任务的阶段。

运行时首页和任务详情顶部均有“终止分析”，点击后显示正在终止并禁止重复提交，已完成检查点保留。历史推荐页可按所选业务日“复盘并更新结果”，显示进度与日志入口；实际AI复盘成功后自动刷新结算结果。

当前任务先冻结官方完整清单、原始响应和规则/程序摘要，再逐场进行不含赔率的23维证据研究。每场独立保存成功检查点；取消、预算用尽或单场失败保留已完成项目，“继续分析”只处理失败/未完成项。规则/程序变化后须新建任务。

“复用近期证据”保留同业务日、同场、规则/schema兼容资料的原时点和来源。报价重新抓取，最终推荐须有新的实际AI决策。任务中心位于`/analysis`，逐场页展示两队对比、来源、反证、失败路径和阵容情景。临场复核、效果与提醒见`research-workflow.md`。

| `FOOT_MATCH_TIMEOUT` | 单场/最终决策每个提供方180秒；未设置时兼容`FOOT_ANALYSIS_TIMEOUT` | 10–3600秒 |
| `FOOT_ANALYSIS_BUDGET` | 每次执行1800秒 | 30–14400秒 |

CLI完整最终结果通过校验后会回收进程组，避免退出阶段挂起拖成超时。心跳仅证明进程存活，不代表研究成功。草稿、发布及复盘始终区分，短连通探测不能替代真实赛事验收。

管理员无本业务日分析记录时显示“开始分析”，已有分析尝试/结果后显示“重新分析”；未执行便取消仍显示“开始分析”，启动失败但尚未执行显示“重试分析”。排队显示“等待分析”，执行/取消中显示相应状态并禁止重复提交。按钮初始HTML与实时更新消费同一action契约，详见[规格035](../specs/035-analysis-action-state/spec.md)。

点击创建持久化任务，后台刷新官方快照并调用本机 CLI；不再只刷新赔率。刷新页面只恢复所选业务日的任务。同一时间只启动一项分析，同业务日重复请求复用正在执行的任务；其他日期任务繁忙时返回409与明确业务日，不把它作为本日任务显示。部分完成仅在存在检查点时展示“继续分析”，新建与续跑不混同。

## 2026-11-05 AI决策修订（规格009，优先于下列旧版说明）

- 先逐场调用AI进行不含赔率的实力/证据研究，冻结结果后再计算可售、可过关、概率和结构候选。
- 候选只是计算结果，不是最终推荐。必须再次取得Claude/Codex实际返回的选择/否决与理由，方可生成完整推荐草稿。每个推荐选项的理由、风险及撤销条件取自已验证的AI返回，缺证据如实标明仅按市场基准。
- 程序保留赔率与p_mkt计算、硬门槛与排名政策校验，AI不能编造概率、改官方价格或绕过发布审查。单场证据阶段和推荐决策阶段均使用同一policy提供方，不静默混合回退。
- 决策失败保留逐场检查点和输入/返回/尝试记录，不回退为机械第一名。发布前核对冻结AI决策及候选上下文，变价/停售或版本变化需要重新分析，不静默换腿。
- 以下测试计数和最小连通探测属于原功能交付记录；009当前验证见`specs/009-ai-decisions/verification.md`，不以历史连通记录保证当前模型可用。

## 提供方顺序

每项新任务只调用当前policy提供方。不存在、认证/限额异常、非零退出、超时、空结果或结构无效时任务标为失败或partial，保留检查点，不自动换提供方。，页面展示执行记录，不把失败当成成功。

逐场研究及最终取舍使用上表`FOOT_MATCH_TIMEOUT`；旧版调用与AI复盘的`FOOT_ANALYSIS_TIMEOUT`默认900秒。超时清理当前CLI子进程组后才回退；清理失败则停止回退。分析不占用gunicorn的60秒请求线程。

可选 `FOOT_CLAUDE_BIN`、`FOOT_CODEX_BIN` 指定可执行文件；留空按 PATH 和本机常用目录查找。沿用本机已配置的账户和默认模型，不复制凭证，不将密钥放入命令、任务输入或执行日志。

Claude 仅加载用户配置以保留已有服务/认证设置；禁用 hooks、Chrome、会话持久化、额外 MCP 和写入/执行工具，只允许 WebSearch/WebFetch。Codex 使用 read-only、禁用执行/桌面/插件工具；除本次调用的 `mcp_servers={}` 外，对本机已配置的MCP名称写入结构完整但禁用的占位传输（`enabled=false,command="/usr/bin/false",args=[]`），避免CLI在禁用前解析桌面专用传输失败。不转发原MCP命令、环境或凭证，不改写全局配置。

## 输出与发布

- 任务状态与脱敏执行记录在 `var/app.db` 的 `analysis_runs`。
- 管理员可在首页或任务详情中查看 `analysis_logs` 的实时公开执行事件：阶段、当前policy提供方、网页工具、公开输出、警告、错误和心跳。日志按游标增量同步，支持提供方筛选、搜索、跟随最新和文本导出；不保存模型私有思考、完整输入回显、原始工具返回或凭证。
- 页面可见时每秒查询增量，后台标签页每3秒查询；没有新 CLI 事件时每15秒记录一次进程存活。每任务保留最近2000条，页面常驻最近600条，每条最多4000字；导出使用全部保留记录。
- 旧任务若未启用日志采集，只显示已有的执行记录和“此任务未保存过程日志”，不补造过程。
- 当前结构化工作流的官方数据、完整规则和哈希冻结在 `runs/<业务日>/<run_id>/input.json`、`rules.md`、`manifest.json`；AI推荐阶段另存 `decision-context.json`、`ai-decision.json` 和 `decision-*/` 中的prompt/schema/response/validated/attempts。旧版 `input-sha256.txt` 属于原交付工件，不代表当前格式。
- 成功结果为 `report.draft.md`，管理员可从任务条进入查看。草稿 HTML 使用 Bleach 白名单清理，不允许脚本、图片或危险协议链接。
- 草稿明确“未审核、未发布”，不会被 `latest_report` 选为正式报告，不会覆盖历史、更新命中率台账或触发推送。
- 当前008/009已实现管理员发起的“刷新官方数据并审核→确认发布”：核对冻结AI决策、候选上下文与官方可售价格，并运行规定的审核脚本。变价、停售、版本变化、工件篡改或硬门槛失败均阻断，不静默换腿。模型声称“已审核”不算审核证据。无人值守自动发布及001旧版“自动纠错至多两次”不在本次实现/授权范围。

## 接口

- `POST /api/recompute`：admin + `X-CSRF`；可选 JSON `{"date":"2026-11-04"}`；202 返回本日任务及action（mode/label/disabled/title），跨日繁忙409返回busy_task与说明，失败返回明确错误。
- `GET /api/analysis/<id>`：admin 查询状态。
- `GET /api/analysis/<id>/logs?after=<cursor>&limit=<1-200>`：admin 增量查询公开日志。
- `GET /api/analysis/<id>/logs/download`：admin 下载最近保存的脱敏日志文本。
- `GET /analysis/<id>`：admin 查看执行记录和未发布草稿。
