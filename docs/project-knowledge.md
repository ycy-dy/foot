# 项目认知文档：足球＋篮球赛事研究 AI Agent 系统

> 面向项目成员、产品人员和后续 AI Agent 的人类可读说明。
>
> 更新日期：2026-11-08
> 文档性质：项目认知与上手指南  
> 当前状态：用户重新确认原推荐要求并添加70%证据可信度硬门槛；现行政策为规格014，支持受控研究、人工发布及每日冻结台账。旧V6文件和编辑器不恢复。

## 1. 一句话认识项目

这是一个面向足球与篮球赛事研究、证据整理、工程维护、人工审核边界和冻结复盘的项目。它不是自动投注系统；当前按规格014执行赛前研究、70%证据门槛和管理员审核发布，自动计划/通知仍停用。

## 2. 最重要的边界

### 2.1 只研究和展示，不投注

系统不连接投注、支付或下单接口，不自动下注，不追损加码。任何文档、页面或通知都不能承诺命中率、收益或正期望。实际投注金额和返还没有业务授权时固定为 `null`。

### 2.2 现行政策与每日台账

用户后续明确沿用原推荐分段与玩法要求，新增70%**证据政策评分**门槛，不达标/缺可靠评分不推荐。[规格014](../specs/014-evidence-gated-recommendations/spec.md)和配套policy/scoring为当前来源；详见[每日推荐与次日复盘](daily-recommendations.md)。研究由当前policy指定的真实Codex/Harness提供方返回，程序做评分与硬审核，管理员确认发布后冻结台账，次日按原票另版复盘。当前独立概率模型未部署，不把证据分或p_mkt当模型胜率。计划和通知仍停用，旧文件/历史目录不恢复。

### 2.3 事实、工程状态和历史工件必须分开

| 内容 | 当前处理 |
| --- | --- |
| 赛程、队伍、时间、赔率、销售状态、赛果 | 仅在获授权任务中使用可追溯来源；缺失写待核/null |
| AI 研究、推荐取舍、复盘解释 | 仅在新规格授权后使用真实 AI；不得用模板冒充 |
| 程序计算和审核 | 只能执行已确认契约；不能自行补业务阈值 |
| 运行工件 | `runs/`、`ledger/`、`var/` 只读核对，不删除或改写 |
| `history/` | 已删除，不恢复 |

### 2.4 不把“已写代码”当成“真实可用”

项目状态区分：已定义、已实现待验收、限定范围已验证、受阻／失败。文档整理不等于运行时测试、发布、部署或生产可用。

## 3. Agent 如何工作（目标，不是当前政策）

按规格014/023授权后，Agent 可按职责协作：编排、数据核验、证据研究、反方检查、决策、确定性审核、人工确认、临场复核和官方结算复盘。当前仅保留职责和安全边界，不保留旧玩法、阈值、维度或页面规则。

## 5. 新成员上手顺序

1. 阅读本文，理解当前014政策、唯一Codex提供方和不投注边界。
2. 阅读[项目治理与阅读地图](project-governance.md)、[系统蓝图](sports-agent-system.md)和[目录约定](directory-layout.md)。
3. 阅读[工程宪法](../.specify/memory/constitution.md)。
4. 按规格014/023的spec、plan、tasks和verification读取当前契约；旧规格仅作实现记录。
5. 修改前检查工作区状态，不覆盖他人已有改动；代码变更先补测试并如实记录验收。
