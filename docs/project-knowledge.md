# 项目认知文档：足球＋篮球赛事研究 AI Agent 系统

> 面向项目成员、产品人员和后续 AI Agent 的人类可读说明。
>
> 更新日期：2026-11-06  
> 文档性质：项目认知与上手指南  
> 当前状态：原分析／推荐体系及页面已删除；无现行业务政策；新分析推荐发布停用待规格013

## 1. 一句话认识项目

这是一个面向足球与篮球赛事研究、证据整理、工程维护、人工审核边界和冻结复盘的项目。它不是自动投注系统，也不在当前阶段生成赛前分析、推荐或发布内容。

## 2. 最重要的边界

### 2.1 只研究和展示，不投注

系统不连接投注、支付或下单接口，不自动下注，不追损加码。任何文档、页面或通知都不能承诺命中率、收益或正期望。实际投注金额和返还没有业务授权时固定为 `null`。

### 2.2 当前没有业务政策

原 V6 阈值、23维证据、玩法结构、概率标签、推荐页面和发布流程均已删除或停用，不得从旧文档、Git 历史或运行工件恢复。规格001–012只作为旧实现记录；规格006目录已删除。规格013完成用户确认及机器可读契约前，不执行新的分析、推荐、审核发布、定时任务或通知。

### 2.3 事实、工程状态和历史工件必须分开

| 内容 | 当前处理 |
| --- | --- |
| 赛程、队伍、时间、赔率、销售状态、赛果 | 仅在获授权任务中使用可追溯来源；缺失写待核/null |
| AI 研究、推荐取舍、复盘解释 | 仅在新规格授权后使用真实 AI；不得用模板冒充 |
| 程序计算和审核 | 只能执行已确认契约；不能自行补业务阈值 |
| 运行工件 | `runs/`、`ledger/`、`var/` 只读核对，不删除或改写 |
| `history/` | 已删除，不恢复 |

### 2.4 不把“已写代码”当成“真实可用”

项目状态区分：已定义、已实现待验收、限定范围已验证、受阻／失败。文档整理不等于运行时测试、发布、部署或生产可用。

## 3. Agent 如何工作（目标，不是当前政策）

未来在规格013授权后，Agent 可按职责协作：编排、数据核验、证据研究、反方检查、决策、确定性审核、人工确认、临场复核和官方结算复盘。当前仅保留职责和安全边界，不保留旧玩法、阈值、维度或页面规则。

## 4. 当前项目结构

| 路径 | 用途 |
| --- | --- |
| `AGENTS.md`、`CLAUDE.md` | 工作入口和项目执行边界 |
| `.specify/memory/constitution.md` | 工程宪法和 Spec Kit 流程 |
| `docs/project-governance.md` | 工程规范阅读地图和状态语言 |
| `docs/sports-agent-system.md` | 目标架构、角色和安全边界 |
| `specs/001-*/`至`specs/012-*/` | 旧实现记录；规格006目录已删除 |
| `specs/013-*/` | 待用户确认的新业务政策规格（若创建） |
| `src/foot_web/` | Flask Web 控制台与分层服务 |
| `tools/` | 审核、核对和迁移工具 |
| `runs/` | 新旧运行工件；只读核对，不因本轮改写 |
| `ledger/` | 历史台账；不改写 |
| `var/` | SQLite、快照、日志和运行时数据；不改写 |

`history/` 已按用户确认删除，旧报告、脚本和体系证据不恢复。不要把 Git 历史或旧路径误写成当前可读文件。

## 5. 新成员上手顺序

1. 阅读本文，理解当前无业务政策和不投注边界。
2. 阅读[项目治理与阅读地图](project-governance.md)、[系统蓝图](sports-agent-system.md)和[目录约定](directory-layout.md)。
3. 阅读[工程宪法](../.specify/memory/constitution.md)。
4. 只有在规格013获用户确认后，读取其 spec、plan、tasks 和 verification；旧规格仅作实现记录。
5. 修改前检查工作区状态，不覆盖他人已有改动；代码变更先补测试并如实记录验收。
