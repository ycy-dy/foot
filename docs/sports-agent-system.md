# 足球＋篮球赛事研究 AI Agent 系统蓝图

更新：2026-11-07。定位：可追溯、可否决、需人工确认的赛事研究与工程系统，不是自动投注机器人。原V6文件/编辑器已删除；当前业务政策为规格014，运行提供方由规格023当前policy声明（目前codex）决定。

## 1. 当前边界

产品认知、工程安全、真实数据、不投注、人工确认和冻结复盘等边界保留。按014/023受控执行研究、审核发布和复盘；自动计划/通知默认停用。旧V6阈值文件/编辑器不恢复，旧运行工件只读，不改写。

系统可保留研究、证据整理、工程维护和历史运行数据核对能力，但不得据此生成新的赛前分析、推荐或发布内容。`specs/001`–`specs/012` 仅是旧实现记录；规格006已删除，不建立链接。

## 2. 当前/目标架构（规格014/023）

以下仅描述未来可审计的职责边界，不表示当前业务已启用：

| 职责 | 主要输入与输出 | 不可越权 |
| --- | --- | --- |
| 编排器 | 任务、运动、阶段、截止边界 → 可取消任务 | 不启动停用的分析、推荐或发布 |
| 数据核验工具 | 官方身份、来源与时点 → 可追溯快照 | 不凭 AI 猜测缺失数据 |
| 研究 Agent | 用户确认的来源与契约 → 证据和缺口 | 不把旧维度或旧模板当现行规则 |
| 反方／风险职责 | 证据 → 反证、失败路径、阻断建议 | 不把“未找到”说成“没有” |
| 决策与审核服务 | 新规格授权的候选与工件 → 审核结果 | 无规格013授权不得生成推荐或发布 |
| 复盘工具 | 冻结工件与官方结果 → 可追溯复盘 | 不改写原票或历史台账 |

任何未来 AI 返回仍不等于事实真实、审核通过或人工发布。保存输入、原始输出、验证结果和哈希；不展示隐藏思维链；双失败不伪造成功。

## 3. 共用平台原则

足球和篮球可以共用身份、来源、任务、审计和展示基础设施，但具体业务政策暂为空。时段、市场、玩法、阈值、维度、概率和输出结构必须等待规格013，不从旧体系推导，也不以程序模板替代用户确认。

## 4. 状态与安全边界

目标状态可包括 `采集 → 研究 → 草稿 → 审核 → 待人工确认 → 发布`，但在规格013确认前，分析、推荐、审核发布和通知状态保持停用。失败、取消、阻断和过期必须可区分；任务完成、AI完成、审核通过、发布成功和台账提升不是同一事实。

必须幂等：重试不重复发布或提升台账；取消后的迟到结果不得恢复成功；来源冲突、截止或版本变化后重新核验。系统不接入投注、支付或下单，不承诺命中或收益。

## 5. 实施顺序

1. **P0 规格013**：用户确认产品边界、业务政策、机器可读契约和停用／启用门禁。
2. **P1 工程映射**：对照既有代码、数据库和旧规格，列出差异，不破坏性改写运行工件。
3. **P2 受控实现**：按 spec → plan → tasks → analyze → implement 补代码、测试和审核门禁。
4. **P3 限定验收**：分别记录模拟或真实证据；不以文件存在、旧工件或文档完成宣称生产上线。

完成定义：每项有可追溯规格、正反测试、明确验收范围和真实状态；代码或配置变更另行测试、部署和健康核验。本轮仅整理文档。
