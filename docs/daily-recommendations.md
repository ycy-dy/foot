# 每日推荐与次日复盘

当前业务政策：[014正文](../specs/014-evidence-gated-recommendations/policy.md)、[机器契约](../specs/014-evidence-gated-recommendations/policy.yaml)、[评分契约](../specs/014-evidence-gated-recommendations/scoring.md)。关联Issue #4。

## 使用流程

1. 登录现有Web工作台（本机端口5020），选择业务日。首页显示完整官方足球/篮球赛程、未开赛可售情况及排除原因；没有已发布新政策结果时明确空状态。
2. 管理员点击“重新分析”，当前policy指定的Codex CLI唯一提供方（Harness可显式切换），逐场保存检查点与来源时点。无真实返回不伪造成功，可取消/续跑；代码或规则变化须新任务。
3. 固定证据政策评分>=70、关键证据完整且无冲突、每选项有研究依据方可进入候选。70分不是70%胜率；市场去水基准与模型概率分开，模型未部署概率/EV为null。
4. 程序核玩法/结构、窗口、真实报价和每中奖分支实际倍数>2.5；AI返回取舍、来源、至少两理由、风险和撤销条件。不足不凑二串一，六类/梦想亦不能绕门槛。
5. 草稿保存report.draft.md、recommendations.draft.json与daily-ledger.draft.json，记录各时段不成串原因。这是研究记录，不等于已发布票。
6. 在“分析中心”进入审核，刷新官方快照、重算门槛并运行独立审核脚本；管理员确认非赔率来源与时点后方可发布。变价、过期、版本变更须重审，不静默换腿。
7. “每日推荐台账”（/daily-ledger?date=YYYY-MM-DD）按业务日查看冻结发布版本、原腿/价格/分支/证据评分/理由/风险/撤销与内容哈希。只有数据库原子推广成功的发布可见；旧无分工件不补认证。
8. 次日在“复盘分析”选**原推荐业务日**，锁定原票与官方赛果做确定性结算，再由AI解释归因；结果另版，AI失败保留上一成功台账。原推荐不覆盖，待定不算输，取消按官方规则。

## 数据位置与口径

- 草稿：runs/业务日/任务ID；包含空时段和失败原因。
- 冻结发布：runs/业务日/publication-ID/daily-ledger.json；audit与AI工件可追踪。
- 台账视图引用既有PublicationsStore和ReviewService，**不建立第二份票数统计**；按ticket_id连接复盘，重复访问不双计。
- 最终推荐、结构研究、六类和梦想分开记录。actual_stake/actual_return固定null，模拟投入和理论返还不写成真实收支。

没有数据、无达标分、AI超时、审核失败都应如实显示状态；服务健康不等于真实比赛分析成功，更不证明盈利。未启用自动计划、自动发布、钉钉发送或投注。
