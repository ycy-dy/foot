# 定时分析与复盘分析（2026-11-04）

规格：`specs/007-scheduled-review/`。

## 定时分析 `/automation`（管理员）

1. 从导航“定时分析”进入，填写名称、类型、北京时间及业务日偏移。
2. 默认停用；勾选“启用每日自动执行”才会自动运行。保存不立即执行，已过时刻从次日开始。
3. 类型可以是“赛前分析”或“赛后复盘”；通常赛前选执行当日，次日复盘选执行前1日。偏移不改变足球/篮球的业务窗口或推荐分段规则。
4. 已有计划直接修改并保存；取消勾选后保存即停用。最多12个计划。
5. 下方记录区区分派发状态与后台任务状态，可点击任务详情查看输出或失败原因。

赛前分析使用规格023当前policy指定的唯一提供方（当前Codex，Harness可显式切换），启用后会消耗账户额度。只生成未审核、未发布草稿；不自动审核通过、不推送、不下单。新复盘也必须取得当前policy指定提供方实际AI分析返回（规格009历史契约已按021/023路由修订），会消耗对应账户额度；原有定时复盘计划仍按既有启停状态执行，本次不自动创建或启用计划。

### 调度机制与故障

- `wsgi`启动每20秒检查的后台线程；测试/普通`create_app()`不自动启动。
- 多gunicorn进程通过`var/scheduler.lock`跨进程锁和SQLite到期唯一键去重，不需要另装cron或launchd服务。
- 服务需在线。重启保留计划；仅补最近15分钟内一次到期任务。离线多日不集中补跑，最近一次也过期则记skipped。
- 同类后台忙时跳过，不把其他日期的任务冒充本次执行。下次仍按计划运行。
- 先持久化派发记录再启动子进程。派发中断不自动重试，以避免重复消耗额度；记录interrupted后需管理员核查已有任务再手动运行。
- 创建人失去管理员权限则跳过；权限配置变更依项目要求测试后重启。
- 停用仅阻止未来派发，不终止已提交任务。计划编辑按当前时间重新计算下次执行。

## 复盘分析 `/reviews`

管理员选择业务日，点击“开始复盘分析”；后台独立进程执行，不阻塞请求，不占用赛前分析的单任务门禁。查看者可读复盘详情，不可发起或修改计划。

- 使用已知标准化台账原票，按原盘口、原选项与原赔率结算；不按mtime猜测异构历史JSON的最终票，不复盘未发布AI草稿。
- 获取官方足球/篮球赛果，校验终场、日期、星期编号与球队身份；业务日跨夜范围取到后2日，未找到/歧义仍待核。
- 逐选项、逐腿、逐笛卡尔分支结算；双平按真实两分支，模拟每分支2元计算成本和理论返还。篮球保持客:主比分及主队让分口径。
- 缺半场、原盘口、未知选项、取消或走盘等明确待核，不自动算输或猜退款。真实金额与返还固定null。
- 复盘报告先列最终推荐复盘汇总与推荐命中率台账，再列分栏统计、逐场选项和逐票分支表；所有赔率均来自冻结原票。
- 缺原赔率时，已知事件命中仍计命中率，未知理论返还不按0处理；Web模拟收益只计算投入和返还均已知的已结算原票，并单列返还待核数量。
- 结算完成后必须调用Claude（失败回退Codex），结构化返回总体总结、全部原票的评估/失败路径/证据缺口/改进建议与限制；缺证据需由AI明确说明，不用固定模板冒充分析。事前概率/证据未保存则不补造，AI解释不能改写确定性结算。
- AI返回的评估、输入和响应哈希、实际提供方与尝试记录可追溯；AI判断不等于已证实原因，不凭一场输赢宣称盈利。
- 无有效AI返回则任务失败、保留诊断工件，不生成完整复盘、不替换上一成功台账。旧版/纯结算报告仍冻结，页面明确未保存AI分析。
- 输入快照、哈希、逐场结果和`review.md`保存在`runs/<业务日>/review-<id>/`，没有`report.md`，因此不挤占正式推荐报告。
- 每次成功生成新版本，SQLite最新有效结算覆盖层供台账/统计读取；失败不替换上一成功版本，重复执行不重复计数。原始`history/`和`ledger/`文件不覆盖。

## 权限与接口

- `GET /automation`、`POST /automation`：仅admin；POST需要表单csrf。
- `GET /reviews`、`GET /reviews/<id>`：已登录成员可读。
- `POST /reviews`：admin + 表单csrf，返回303到后台任务详情。
- `GET /api/reviews/<id>`：已登录成员查看公开状态，不返回后台PID或创建人ID。
- 管理员保存计划/触发任务、定时派发及复盘完成/失败均写审计日志。

## 运行时数据

`var/app.db`增加`schedules`、`schedule_fires`、`review_runs`和最新复盘覆盖层；建表幂等，无破坏性迁移。应与现有数据库一起备份。不要直接运行`ledger/data`中的历史抓取/结算脚本作为线上服务，它们有固定日期和覆盖式输出。
