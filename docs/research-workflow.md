# 证据研究与复核闭环

任务中心连接逐场证据、AI推荐决策、审核发布、临场复核、复盘台账及效果中心。仅做研究与展示，不接入投注或支付，不保证命中或收益。

## 证据和推荐

逐场页展示完整23维两队对比，篮球客队在前。来源保留发布时间、适用时点、等级和去重组；未知保留待核，智能体自报核实仍待人工复核。阵容情景记录条件、影响和动作，不赋予概率。

事实否决必须关联有时点的L1/L2已核实非赔率维度。资料缺口只能降级，不能冒充已确认反证。查不到非赔率依据的方向明确写“仅按市场基准”。

`p_mkt`由官方完整同源同刻市场比例去水计算，组合仅为独立近似。模型概率和EV保持null。程序计算分支、硬门槛和候选，实际Claude/Codex返回取舍、理由、风险与撤销条件。八结构、六类、分段主推荐及四比分梦想单分别保留。

发布前刷新官方快照、验证AI工件并执行审核脚本；检查每个选项的理由、来源/缺口、p_mkt、失败路径和撤销条件。通过后由管理员确认发布。规则/代码或官方候选上下文改变后要求重新分析，不静默换腿。

## 临场复核

当前报告可手动提交复核；管理员也可在`/research/monitoring`开启定时复核。默认关闭，提前量15–180分钟，间隔5–60分钟。

复核对照比赛身份、开赛/销售状态、盘口、价格、完整市场基准及组合门槛。选择补核首发与伤停时调用实际Claude/Codex，保存返回及来源追溯；只研究进入提前量范围的比赛。缓存沿用原核查时点，不伪装新发现。

变价、身份变化或重要证据变化提示重审；不自动换腿、替换发布版本或改写原价。首发不明、预算不足、部分返回和进程中断都有状态，已保存材料保留。撤销仅改变展示状态，原票仍可复盘。

## 复盘和效果

新发布原票接入现有复盘。程序按官方赛果结算，后台正式复盘必须另有实际AI归因返回才提升新台账版本。再次复盘不重复计数，未知赛果留待定；实际金额与实际返还固定为null。

`/research/evaluation`展示：

- 事前市场基准、实际命中、覆盖比赛、重复事件和缺失概率。
- 二元Brier、Log loss及概率分档；0/1仅在Log loss中按1e-15裁剪。
- 同一发布快照和时点的纯市场研究对照与实际AI选择，按各时段冻结原票选择版本，含撤销记录。两策略均有赛果及原始概率才进入共同评分。
- AI追溯覆盖；旧记录不补造概率、AI身份或结果。

整单损失不推出每腿都失败，待定不算未中。共享比赛、时点及组合独立近似的局限保留；二元Brier不与历史三分类Brier直接比较。独立预测模型尚未部署，评分不能用作盈利或命中率提升承诺。

## 版本与通知

`/research/versions`展示规则MD/YAML、工作流和Python代码摘要，以及程序支持的机器门槛。规则/程序变化使旧审核失效。列明项通过不代表已经理解或实现全文策略变化。

定时分析与次日复盘沿用`/automation`，默认没有启用计划。临场复核和钉钉提醒也默认关闭，不因部署自动启用。

钉钉提醒需配置企业应用、AgentId及白名单内的`FOOT_NOTIFY_USER_IDS`，由管理员选择已登记回调对应的报告入口并明确启用。只收集启用后的新发布、复盘、撤销、临场变化和任务失败，不补发历史事件。

接收人或应用变化后需重新确认，旧待发事件不转投新目标。获取凭证前失败最多重试三次；发送中超时或进程中断记为结果待核，不自动重发。接口接受仅显示“已提交，接收未核”，不声称已送达。测试通知只有管理员主动点击才入队。
